# Customer Segmentation Explorer

An interactive Streamlit application that visualises and explores customer segments
generated by a K-means clustering model. Built for marketing managers and CRM analysts
who need actionable segment insights without writing code.

---

## Project structure

```
customer_segmentation/
├── app.py                  # Main Streamlit application
├── config.py               # All constants and configuration values
├── requirements.txt        # Pinned dependency versions
├── README.md
├── model/
│   ├── train.py            # Standalone training script (run once)
│   ├── kmeans_model.pkl    # Serialised KMeans model (generated by train.py)
│   └── scaler.pkl          # Serialised StandardScaler (generated by train.py)
├── data/
│   └── customers.csv       # Mall Customers dataset
└── utils/
    ├── __init__.py
    └── helpers.py          # Reusable functions: loading, preprocessing, plotting
```

## Setup

**1. Clone or download the project**

```bash
git clone <repo-url>
cd customer_segmentation
```

**2. Create and activate a virtual environment (recommended)**

```bash
python -m venv venv
source venv/bin/activate        # macOS / Linux
venv\Scripts\activate           # Windows
```

**3. Install dependencies**

```bash
pip install -r requirements.txt
```

**4. Add the dataset**

Download Mall_Customers.csv from Kaggle, rename it to customers.csv,
and place it in the data/ folder.

**5. Train the model (run once)**

```bash
python model/train.py
```

This generates model/kmeans_model.pkl and model/scaler.pkl.

**6. Launch the app**

```bash
streamlit run app.py
```

The app opens automatically at http://localhost:8501.

---

## Reproducibility

All stochastic operations use random_state=42 (set in config.py).
Dependency versions are pinned in requirements.txt.

---

## Key design decisions

- Training and inference are fully separated. The app never calls train.py.
- All constants are centralised in config.py — no magic numbers scattered across files.
- Expensive computations are cached via @st.cache_data and @st.cache_resource.
- User inputs are validated before reaching the model, with clear st.error() messages.
